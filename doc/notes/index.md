# GEMM 基础与核心概念

## 1. 什么是 GEMM？

**GEMM** 全称为 **General Matrix Multiply（通用矩阵乘法）**，是基础线性代数子程序库（BLAS）中最核心的算子之一。

### 最基础的算式
本质上，它就是最简单的高中矩阵乘法：

```text
C = A × B
```

### 标准库（BLAS）中的完整算式
在工程和标准库中，GEMM 扩展为带有缩放因子的标准形式：

```text
C ← α · op(A) · op(B) + β · C
```

**参数说明：**
- **`A`**：`M × K` 维度的输入矩阵
- **`B`**：`K × N` 维度的输入矩阵
- **`C`**：`M × N` 维度的目标输出矩阵
- **`α, β`**：标量系数（当 `α = 1, β = 0` 时，简化为最纯粹的 `C = A × B`）
- **`op(X)`**：表示可选择不转置、转置（`Xᵀ`）或共轭转置（`Xᴴ`）

---

## 2. 它在代码里其实就是什么？

在计算机底层实现中，GEMM 最朴素的原型其实就是**三个相互嵌套的 `for` 循环**：

```c
for (int i = 0; i < M; i++) {
    for (int j = 0; j < N; j++) {
        for (int k = 0; k < K; k++) {
            C[i][j] += A[i][k] * B[k][j];
        }
    }
}
```

> **直观理解**：拿矩阵 `A` 的第 `i` 行与矩阵 `B` 的第 `j` 列，对应位置相乘并累加，填入目标矩阵 `C` 的第 `(i, j)` 格子里。

---

## 3. 为什么还要学“优化”？

如果直接使用上面的朴素三层循环：

1. **计算量庞大**：计算两个 `1024 × 1024` 的单精度浮点矩阵，需要执行约 **20 亿次浮点运算**（`2 × 1024³` FLOPs）。
2. **算力浪费严重**：如果不做任何优化，CPU **95% 以上的时间都处于等待从主内存读取数据的阻塞状态**，实际发挥出的性能往往不足 CPU 理论极限的 **5%**。

::: tip 优化追求的核心目标
“单核优化技巧”本质上只做一件事：

**把这三层 `for` 循环拆开、重排顺序、化整为零（分块 Tiling），让数据尽可能留在就近的高速存储（CPU 寄存器与各级 Cache）中，避免让 CPU 闲等内存，将芯片算力压榨到极限。**
:::
